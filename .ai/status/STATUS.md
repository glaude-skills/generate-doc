# 상태

- 2026-09-05: v0.1.0 초기 배포. SKILL.md + 플러그인 매니페스트.
  - RED/GREEN 검증: 두 과제로 스킬 유무 비교. 둘 다 출력 차이 확인.
- 2026-09-06: 문서에서 특정 문서 종류(이력서) 중심으로 읽히던 부분 정리.
  - README의 before/after 예시 섹션 삭제. 설치, 트리거, 금지 목록만 남김.
  - SKILL.md의 유일한 예시를 CLI README 소개 문단 케이스로 교체.
  - 프론트매터의 트리거 키워드는 유지. 빼면 해당 요청에 스킬이 안 걸린다.
- 2026-09-06: v0.2.0. 긴 하이픈 절대 금지 규칙 추가.
  - "쓰지 않는 표현" 맨 앞에 배치. 대체 방법 표, 최종 검사 항목, 자기합리화 반박까지 3중.
  - 저장소 문서 자체의 em dash 6개도 제거. 규칙을 어기는 문서를 두면 스킬을 믿을 이유가 없다.

- 2026-09-06: v0.2.1. 짧은 하이픈 `-` 은 제한 없이 허용. 금지 대상은 em dash와 en dash 두 개뿐.

- 2026-10-07: v0.3.0. 사람이 쓴 문서처럼 쓰는 지침을 녹였다. 기존과 겹치는 내용(서론 금지, 추상어, 상투어, 사실 지어내기)은 그대로 두고 없던 것만 넣었다.
  - 일을 설명하는 문서의 흐름(상황, 문제, 판단, 조치, 결과, 남은 과제)과 고민한 흔적 남기기
  - 규칙 12~14: 확신의 정도를 근거에 맞추기, 설명 밀도 다르게 두기, 제목이 내용을 말하게 하기
  - 쓰지 않는 표현에 꾸밈말, 같은 어미 반복, 굳이 안 써도 되는 영어 추가. 기존 목록은 줄이지 않았다.
  - 문서 종류별로 다른 점(업무 문서, 기술 문서, 회의록, 보고서, 자기소개서) 절 추가, 최종 검사 8개 항목 추가
  - RED/GREEN: 장애 보고서 과제는 차이가 뚜렷했다. 새 버전은 제목에 원인과 조치를 썼고, scalability를 "트래픽이 늘었을 때 버티는지"로 풀었고, 원인을 "판단이고 확정된 사실은 아니다"로 구분했다. 회의록 과제는 v0.2.1도 이미 결정과 논의를 나눠 써서 차이가 거의 없었다.
